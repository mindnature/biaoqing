# GIF Sticker Studio V3.0｜真正逐帧角色表演

## 为什么要升级

V2 虽然会生成 16 帧分镜和验收轮廓，但用户实测会被某些智能体降级成「一张静态角色图 + 整体摇摆」。V3 改成 **完整动作默认 + 实际姿势门禁 + 禁止静默降级**。

参考高质量表情：16 帧、约 140ms/帧，眼神、眉毛、嘴、头部朝向、手臂、肩膀和重心连续变化；字幕固定，不是整张画动一动。**不将用户的原始角色参考图上传公共 GitHub**。

## V3 和 V2 的关键差异

| 维度 | V2 | V3 |
|---|---|---|
| 默认 | 靠描述选择流程 | 完整角色表演为默认 |
| 动作规划 | 分镜文案 | 16 帧分镜 + 动作锚点审查 |
| 质量门禁 | 空白、裁切、位置、颜色 | 再增「剔除整体位移/缩放后的人体局部变化」 |
| 轻动态替代 | 易被调用方误用 | 明令禁止无授权降级 |
| 出口 | 允许最低 4 帧 | 微信压缩后保留至少 12 帧并重新验收 |
| 验收 | 原始帧 | 源帧 + 最终 GIF 双验收，且人工复核不可替代 |

## 一、生成独立动作帧

```sh
python scripts/studio_v3.py plan --character "示例角色" --reference "assets/character.png" --actions "哈哈,委屈,收到,哼,嗯？,晚安,早安,加油,拜拜" --output workspaces/demo
```

产生 `production.json`、`prompts/*.txt` 和 `frames/<slug>/`。每条动作需要 16 张同尺寸、同一角色、**真正不同姿势的透明 PNG**，用 `000.png` 到 `015.png` 命名。固定视角和尺度，不许文字。先校验第 0、5、8、15 帧的脸和服装身份，再生成中间帧。

支持把 4×4 透明姿势图集准确切分成 16 张，但格子可能存在偏移；必须目视核对裁切和相邻动作：

```sh
python scripts/studio_v3.py import-atlas atlas.png workspaces/demo/frames/hmph
```

**注意：本仓库未内置图像生成模型。** 智能体必须使用它本身实际拥有的合法图像工具生产关键帧；仅靠 Python 文件本身无法从单张参考图创作真实角色动画。

## 二、表演门禁

```sh
python scripts/studio_v3.py inspect workspaces/demo/frames/hmph --report workspaces/demo/hmph.json
```

技术指标先按前景边界裁剪、缩放归一化，剔除「整个角色上下弹跳、左右晃动、缩放」造成的假差异，再检查多个独立造型、上半脸头区域和身体手臂区域的变化。少于 12 帧、无独立造型、缺乏协同变化或 V2 基础技术错误时，停止打包。

报告可能出现：
- `whole_sprite_only`：消除位移与缩放后大部分帧一样，应重做真实动作。
- `not_coordinated_acting`：脸/头和身体/手臂没有足够的局部变化。
- `too_few_keyframes`：有效帧不足。
- `clipped_or_no_gutter`、`empty`：角色截断、透明边距不足或空帧。
- `review_required`：提示人工检查，特别是动作幅度很大的转头、拥抱等可能被误报。

这些是**启发式质量筛查，不是语义动作识别**；既可能有误报，也可能漏掉坏脸坏手，不能替代逐帧人工验收。

## 三、全流程导出

```sh
python scripts/studio_v3.py build workspaces/demo/production.json --font "/path/to/chinese-font.ttf" --heart
```

强制进行：16 张真实姿势检查 → 4×4 动作图集 → 16 帧 140ms 无字原始 GIF → 固定字幕叠加 → 微信目标大小压缩（默认 500000 字节、至少保留 12 帧）→ 成品 GIF 再次做姿势门禁 → ZIP 与报告。

出现**只有轻动态**、源素材残缺、压缩后损失动作等问题，停止报告失败，不要输出冒充完整角色表演的成品。原有轻动态脚本仍供**用户明确指定轻动态**时使用。

## 四、质量底线与限制

- 一条表情一套独立演出；哈哈、委屈、收到、哼必须动作不同，不能仅换文字。
- 文字由程序后期统一绘制，粉红粗字、白描边、小爱心；不让生成模型在关键帧画中文字。
- 保留参考人物的脸、比例、颜色、衣服和装饰；每帧应具有可解释的动作连续性。
- 必须检查同一角色每帧手部、面部、服饰、循环首尾；GIF 本身合格不等于平台批准。
- 任何未获用户验收的新动作，只能报告为待确认。工具无法自动重绘坏手和人脸，应调用图像生成工具生成替换帧。
- 不准把用户私人角色图片放进公开仓库；`workspaces/` 默认忽略。

## 五、先做一张，再批量

先制作「哼」的 16 帧角色表演，检验每帧的表情、眼神、肩膀、手和身体。如果角色一致性通过，再扩展到 8—16 个常用词，避免一次性生成大量失败样品。
