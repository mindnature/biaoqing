# GIF Sticker Studio V4.0｜从单张角色参考图到真实动态表情包

## 核心变化

以前的默认入口能够规划动作并处理现成的16张 PNG，但**没有直接接收图生视频或生成的 GIF 作为完整动作素材的入口**。V4 新增实际视频/GIF/PNG 导入器、真实视频抽帧、简单透明抠像、统一坐标、动作周期启发式选择、浏览器离线可视化审核、与 V3 的批量 GIF 构建桥接。

V4 的“模型生成”是一份**与外部智能体对接的生产协议**，不是仓库内已存在的图像/视频模型。若使用 Codex、Claude 或其他媒体工具，需由当前智能体先确认实际有可调用的视频/图片生成能力、调用额度及授权，并且产出真实文件，后续代码才能处理；没模型的用户仍可使用已有 GIF、MP4 或连续 PNG。

## 轻量安装

Python 3.10+，Pillow（\`pip install -r requirements.txt\`）。若需要导入视频，还须独立安装 **FFmpeg 并加入 PATH**；导入 GIF 或 PNG 目录不需要 FFmpeg。无需 Docker、PyTorch、RIFE 或专用 GPU。视频帧的复杂背景分割没有内置模型；推荐先让生成模型输出**固定机位、纯绿幕或紫幕、无字幕、独立角色的动作**。

## 方案 A：图生视频 → GIF（优先完整肢体表演）

\`\`\`sh
python scripts/studio_v4.py plan \
  --character "示例角色" --reference "assets/character.png" \
  --actions "好的,哈哈哈,生气,拜拜" --output workspaces/sample

# 查看 generation/okay-video.txt（每条表情一个视频生成提示词）。
# 让已连接且获得使用者授权的生成工具产出真正的 action.mp4。
# 注意：本地 CLI 不直接调用外部视频模型，也不会默默购买 API 额度。

python scripts/studio_v4.py import workspaces/sample/production.json \
  okay path/to/action.mp4 --background auto --start 0 --duration 2.8 --mode cycle
python scripts/studio_v4.py review workspaces/sample/production.json okay

# 批次四个表情均有可用帧并经过验证后：
python scripts/studio_v4.py build workspaces/sample/production.json \
  --font "/path/to/licensed-CJK-font.ttf"
\`\`\`

导入程序会读取 MP4/MOV/MKV/WebM，用 FFmpeg 以16fps抽取最长20秒的指定片段，再进行绿色/紫色色键或 alpha 处理，统一角色在所有帧中的坐标，并选取16个真实不同时间点的姿势。\`--mode cycle\` 优先搜索较低首尾差异的窗口，\`--mode one-shot\` 不会强迫一次性表演伪装为周期运动，\`auto\` 默认尊重片段先后次序。**并不会自动纠正所有视频生成的脸变形、手错乱和运动跳变**。

缺少 \`ffmpeg\` 会直接报错；不透明、非纯色背景会提示需要外部抠像方案，而非声称已完成透明处理。与主体同色的绿色/紫色区域也可能被误抠，须人工检查并改用不同色键或其他分割方式。

## 方案 B：图像关键帧 → GIF

\`plan\` 同时生成 \`prompts/<slug>.txt\`，由有实际图像能力的智能体产生16张身份一致的动态姿势 PNG，按 \`000.png..015.png\` 命名。用户也可用 V3 的 \`import-atlas\` 分解 4×4 动作图集。这条路线能较准确保持某种插画/像素画风，但**并不保证单次模型生成16帧就是自然动画**，必须预览。

## 方案 C：直接导入已有素材

\`\`\`sh
# 原本已经有透明动画 GIF（可有色键背景）
python scripts/studio_v4.py import workspaces/sample/production.json okay input.gif

# 用户提供包含至少16张真正不同姿势的PNG/JPG/WebP文件夹
python scripts/studio_v4.py import workspaces/sample/production.json okay path/to/frames/
\`\`\`

不允许从8张照片复制重复帧凑成16张表演。原素材若没有真实运动变化，检测结果会标为 \`blocked\`。导入时不覆盖已经存在的 000.png～015.png，以防丢失用户手工修复的动作；要替换须新建工作区或人工备份处理。

## 离线审核

\`\`\`sh
python scripts/studio_v4.py review workspaces/sample/production.json okay
\`\`\`

生成 \`workspaces/sample/review/okay.html\` 和联系表及 JSON 报告。用浏览器直接打开 HTML，可以播放/暂停、上一帧/下一帧、快速对照16帧，并突出提示有风险的帧。所有图片嵌入 HTML，**不需要启用服务器、不通过网络上传用户角色图**。这不是直接在网页上自动修复脸、手或动画的编辑器；发现坏帧应该重新绘制/生成对应帧，再重跑 review。

## 已有 V3 导出能力与默认约束

- 默认 16 个独立 GIF，4个一批。每张输入16帧真实角色动作；压缩时最少保留12帧。
- 最终方形、循环，默认上限 500000 字节；字幕按素材画风自动选配、固定文字位置、后期叠加，无色条底板。
- \`studio_v4.py build\` 复用 \`studio_v3.py\` 的质量检查、字幕及 ZIP 打包。所有四个动作必须已真实存在；代码不会在缺失时假装已生成。
- 自动颜色/动作/循环检查是启发式；需要用户真正预览、检查角色一致性、动作流畅性与最终平台规格。

## 与 sprite-gen 的关系和许可证

本项目参考了公开的 **sprite-gen** 项目所采用的“生成素材 → 动作帧提取 → 质量审核 → 图集/循环导出”**架构思路**，但此 V4 模块为单独编写的轻量实现，**没有移植 sprite-gen 的 Apache-2.0 源代码**，也没有将其复杂游戏引擎、场景、行走姿态算法或 RIFE 大型依赖复制过来。若未来实际移植代码，须遵守对应开源许可并在仓库保留适用的版权声明。

需要更强的视频抠像、模型接口、逐帧插补和交互式修改功能时，可通过独立的、经过用户授权的供应商适配层继续扩展，但这些能力并非 V4 已实现的功能。
